# 物理知识图谱构建与交互探索

> 作品集内容草稿。发布前按实际职责补充个人贡献，并完成截图与上游证据核对；不把待实现功能写成已经完成。

## 项目简介

围绕物理教材中的知识概念与关系组织，探索从教材解析、领域知识抽取到图谱检查与交互查询的流程。在已有 Kgraph 应用基础上整理本机演示，通过 Neo4j、FastAPI、Vue 3 与 D3 实现知识点搜索、节点详情、分级展示和一跳关系探索。

当前仓库包含独立演示 JSON：101 个节点、104 条有方向的关系。完整流程与各阶段状态见 [项目流程](PROJECT_PIPELINE.md)。

## 主要功能与展示案例

| 功能 | 用户操作 | 当前结果 |
|---|---|---|
| 图谱总览 | 打开初中物理演示 | 101 节点、104 条真实关系，类型颜色图例 |
| 模糊搜索 | 输入电荷 | 展示五个候选，选择后查询具体实体 |
| 分级展示 | 切换核心/重要/全部 | 基础节点分别为 9/52/101 |
| 一跳探索 | 核心层选中力 | 基础9 + 新增6，显示15节点/8关系 |
| 连续探索 | 点击关联节点 | 替换当前临时邻域，保留基础图谱并去重 |
| 恢复视图 | 点击返回分级视图 | 恢复原层级节点与关系 |

节点颜色表示实体类型，大小表示完整图谱中直接关联的不同节点数量；均不作为知识点重要程度或学习难度的判断依据。

## 关键问题与技术选择

| 问题 | 采取的措施 | 需要展示的证据 |
|---|---|---|
| 双栏教材解析顺序错乱 | 从 PaddleOCR 尝试转向 MinerU | 同页解析对比；以实际结果说明改善 |
| 通用抽取在物理领域不稳定 | 探索领域实体类型、关系约束与规则校验 | 抽取错误与领域规则处理案例 |
| 重复实体或关系端点不一致 | 合并、统一 ID 与校验 | 真实合并记录或输入输出对比 |
| 仅有图谱图片，难以定位知识 | 搜索候选、按 ID 查询与节点定位 | 电荷五个候选及详情截图 |
| 分级筛选使节点缺少可见邻居 | 保留基础图谱并补充当前一跳关联 | 力节点展开及返回截图 |
| 连续选择导致节点累积或视图跳动 | 从基础图谱重新合并，保留已有坐标并处理过期响应 | 连续选点的操作录像或验证结果 |

不填写未经测量的准确率、响应速度或提升百分比。

## 技术栈与边界

当前演示：Python、FastAPI、Neo4j、Vue 3、Element Plus、D3、JSON 校验与导入。上游项目经历涉及 MinerU、GraphRAG-more、PhyKgraph 和 Gephi；其材料需另行补充。

题目解析与语义检索计划直接针对当前 JSON 构建独立索引，通过实体 ID 连接 Neo4j；尚未接入本演示。嵌入模型未确定，不写成已使用 BGE-M3；本地索引若未使用 LanceDB，也不将其列入演示技术栈。

历史项目使用过 38,942 节点、21,474 关系的数据，完整数据不包含在本仓库。发布时附上对应统计证据；当前小图与历史图谱的抽样关系未经确认，不称为已验证的子集。
